# AI 規劃模式（/brainstorm）

把模糊的想法變成具體的計劃書。透過引導式問答，幫你在 AI 動手寫 code 之前，先釐清「到底要做什麼」。

> 致謝：核心理念參考自 [obra/superpowers](https://github.com/obra/superpowers)（brainstorming skill, MIT License），經過簡化與在地化改造。

---

<HARD-GATE>
在用戶確認計劃書之前，絕對不可以：
- 寫任何程式碼
- 建立任何檔案（計劃書本身除外）
- 執行任何實作動作
- scaffold 任何專案結構

不管任務看起來多簡單，都要先走完規劃流程。
一個待辦事項 App、一個簡單腳本、一個設定檔修改，全部都要。
計劃書可以很短（簡單任務幾句話就夠），但流程不能跳過。
</HARD-GATE>

## 輸入格式

- `/brainstorm 我想做一個記帳 App` — 帶主題啟動
- `/brainstorm` — 不帶主題，AI 會問你想做什麼

計劃書存放位置：`100_Todo/plans/YYYY-MM-DD-[主題].md`

---

## 流程（按順序執行，不可跳步）

### Phase 0：確認溝通模式 ⭐ 最重要的第一步

用 **AskUserQuestion** 問：

> 你希望我用什麼樣的程度，跟你進行專案與需求的討論及展開？

選項：
1. 🟢 **小白模式**（推薦給非工程師）— 白話講，少技術名詞，重點放在「你會得到什麼」
2. 🟡 **半技術模式** — 保留必要技術名詞，搭配說明
3. 🔴 **工程師模式** — 直接用技術詞彙，最精簡
4. 🤔 **你決定就好** — AI 看情況自動調整

將選擇記為 `COMMUNICATION_MODE`，後續每一句話都套用。

#### 小白模式規則
- 用「網頁設定檔」不用「config.js」、用「自動執行的腳本」不用「cron job」
- 每個方案先說「做完你會看到什麼」
- 假設列表改寫成成果導向，不出現純技術詞彙
- 方案比較表欄位：「做完長什麼樣」「優點」「缺點」「可能的風險」「未來能延伸」「你需要做的事」

#### 半技術模式規則
- 保留檔名、套件名、API 名稱等關鍵詞
- 第一次出現專業名詞時加一句白話說明

#### 工程師模式規則
- 直接用技術詞彙，不需解釋

---

### Phase 1：暖身確認

**Step 1-1：確認主題**
如果用戶 `/brainstorm` 後面有主題直接用；沒有則用 AskUserQuestion 問一句話描述。

**Step 1-2：分類**
用 AskUserQuestion 問：
1. 🆕 做一個新東西
2. 🔧 解決一個問題
3. ✨ 改善現有的東西
4. 🤔 我還不確定

記為 PROJECT_TYPE。

---

### Phase 2：快速探索

**Step 2-1：掃描上下文（AI 自動執行）**
- 讀 CLAUDE.md（如果有）
- 看最近 5 筆 git commit
- 用 Glob 掃描專案結構
- 找到主題相關的程式碼

**Step 2-2：列出假設**
列出 3-5 個理解和假設，套用 COMMUNICATION_MODE。

用 AskUserQuestion 問：
1. ✅ 全部正確，繼續！
2. ✏️ 有些要修正
3. 🔄 大部分都不對，重新來

---

### Phase 3：深度釐清

一次問一個問題，最多 5 個。永遠用 AskUserQuestion。優先選擇題，最後一個選項留給自由輸入。已在假設確認過的不再問。

不耐煩偵測：用戶說「直接做吧」「你決定」→ 最多再問一個關鍵問題，直接進 Phase 4。

---

### Phase 4：方案提議

提出 2-3 個方案，套用 COMMUNICATION_MODE。

半技術 / 工程師模式比較表欄位：做法、優點、缺點、適合、預估工作量

小白模式比較表欄位：做完長什麼樣、好處、壞處、可能的風險、未來能延伸什麼、你需要做的事

用 AskUserQuestion 讓用戶選方案。

---

### Phase 5：計劃書生成

**Step 5-1：撰寫計劃書**

```markdown
# [計劃名稱]

> 建立時間：YYYY-MM-DD HH:MM
> 類型：[新功能 / 問題修復 / 改善優化]
> 狀態：待執行

## 你要做的事（一句話版）
[最白話的描述]

## 背景和動機
[為什麼要做？解決什麼問題？]

## 具體步驟
### Step 1：[名稱]
- 做什麼：
- 產出：
- 注意：

## 預計成果
- [成果 1]
- [成果 2]

## 不包含在這次的範圍
- [明確列出]

## 可能遇到的風險
- [風險]：[怎麼處理]
```

**Step 5-2：Self-Review（AI 內部，不告知用戶）**
1. 有無 TBD / 待確認 → 填上
2. 步驟間有無矛盾 → 修正
3. 步驟超過 8 個 → 考慮拆分
4. 有無模糊指令 → 改具體

**Step 5-3：存檔**
存到 `100_Todo/plans/YYYY-MM-DD-[主題].md`

---

### Phase 6：下一步

用 AskUserQuestion 問：
1. 🚀 現在就開始執行！
2. 📝 我想先修改計劃書
3. 💾 先存著，之後再做

---

## 護欄（永遠生效）

- 確認計劃書前不寫任何 code
- 不跳 Phase（簡單任務每個 Phase 幾秒過完，但不能跳）
- 一次只問一個問題
- 能用 AskUserQuestion 就用
- 不說「好問題」「很有趣」等空洞附和
- 套用 YAGNI 原則，只留現在確定需要的功能
- 全程繁體中文（含執行階段的進度訊息）
  - 例外：thinking block、工具參數、程式碼變數名稱
