# 報價分析、入庫與歷史價格引用共用規則

所有廠商報價（採用、未採用、待決定）都逐項分析、存檔及入庫。採用狀態與分析完成狀態分開；未決定不標未採用，沒實際檔案不產生虛構分析。依完整報價流程已授權時不再逐項詢問。只要求預覽則不寫入。

## 每項最低分析與新案查價

- 每項核對原數量×單價、計量單位、規格、稅基、供料／安裝／運輸等範圍、時點、可比價格與來源；缺資料也記原因。工料拆解可標缺依據，不自填固定比例。
- 優先查既有單價庫，不每案例行重詢。依條件分「可直接引用／有依據調整／僅供比較／待补資料或詢價」。同名、最低價、成交過或未採用，都不單獨決定可用性。
- 新案採用保留來源價格ID及版次快照、規格差異、調整算式與依據、採用數量／成本及目標位置。原價、成交價、估算價、售價分開，不覆寫原來源。
- 每式合包不得無依據轉成每平方公尺；整包議價不得無依據分配成逐項成交價。沒有統一舊價加成或到期天數，依原有效期與個別工種證據核對。
- 案件relation未知、來源不足、稅別衝突時可暫存待補，不能標可直接引用或正式入庫完成。價格可共用參考，但僅YASHI／YUSHI記帳，工程價格不自動產生分錄。

## 分析

1. 取回同案同工項各家原報價、版本、日期、數量單位、規格、含未稅條件及付款／交期／保固／除外項目。已有圖說與標單一併核對；無圖說仍可做文件金額與條件比較，把規格符合性列待核對，不跳過整份分析。
2. 檢查數量×單價、小計、折讓、稅額及總額；保留原始數字，差異單列，不自行修正原始報價。
3. 比較同範圍與同稅基的單價、總價、規格、漏項、施工界面及付款條件。缺項不當成零，差異不可比時明列原因，不直接按最低總價排名。
4. 若已有選定 B 廠商及核定成交價，A、C 可與 B 對照；明確區別 B 原報價與議價後成交價，不把不同範圍的差額全解釋成議價成果。沒有 B 報價或未選定時只分析手上資料，不等待假定的決標结果。
5. 未採用原因只記使用者提供或有文件佐證的內容；價格較高不自動等於未採用原因。分析建議與已確認決策分開。
6. 合理性優先引用本案可比報價、過去正式成交與可追溯規格資料。需要市場行情時查明來源與日期，區分參考價與成交價；沒有足夠依據就寫無法判定，不憑印象估值。只有需要工料拆解時才接 [工程單價契約分析](../../工程單價契約分析/SKILL.md)，不把整份報價比價強制轉為契約單價拆解。

## 存檔與驗收

- 分析成果預設存共用根目錄 `400_Knowledge/工程/報價分析/YYYY-MM-DD_案件名_工項_報價分析.md`；使用者指定位置優先。若本案已有報價合理性分析文件（例如原 STEP 1.3 產物），更新既有文件中本次報價分析章節，保留原章節及來源，不產生兩份相同結論。必要的新修訂檔名加版次，不能覆蓋未讀取內容。
- 報告包含：結論、來源清單（檔案／Notion連結、報價編號版次及日期）、各廠商比較表、算術與漏項核對、規格／範圍差異、稅別與付款條件、採用狀態及原因依據、議價重點、待核對事項、可供日後引用的適用條件。
- 一份同工項比較報告可以涵蓋 A、C 及 B 參考資料，不必每家各建重複報告。原報價留在原報價歸檔位置，未採用報價不移入「已發包」資料夾。
- 讀回成果確認實際存在、來源及數值可追溯；回覆實際檔案連結。分析完成不改發包決定、不增加案件已發包成本、不建立付款或分錄。
- 完整入庫須完成本機分析報告、原檔歸檔、Notion價格明細及文件／分析關聯；先查重沿用既有記錄。Notion分析可存既有頁面章節，不必另建重複頁。任一步失敗標待同步，不以本機存檔冒稱全部完成。
