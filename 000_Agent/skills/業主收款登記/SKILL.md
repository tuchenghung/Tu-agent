# 業主收款登記

先讀 [共用資料連動規則](../vendor-award-registration/references/data-linkage.md) 的共用原則、資料來源、收付款計算、交易連動及寫入恢復；不在本檔重複維護資料庫 ID 和科目名稱。

## 整理與定位

解析唯一案件、實際收款日期、本次實收金額、款項類型、實際入帳帳戶、來源交易參考及是否沖應收。明確授權且資訊完整時先摘要直接登記；只有關鍵資訊不足才詢問。

日期用使用者提供的日期或明確的「今天」；歷史交易或未提供日期時先取得實際收款日，不能自動預設今天。

從案件「收款紀錄」完整關聯找對應待收／部分收排程，優先沿用。多筆候選以期別、應收與未收、合約來源辨識；不能只因同額就選定。沒有排程才建立，已收清的排程再有款項須先查是否追加、重複或其他期別。

只有請款單／預計收款不建立實收或現金分錄。僅說收到但未提供金額，不能用合約額或應收額當實收。實際收款與合約稅額不得自行換算混用。

## 累計與執行

1. 讀原排程應收 E、實收 R0；本次 A，更新後 R=R0+A。R<E 為部分收、R=E 已收；超額先查原因，不把應收改大來消除差額。明說分期且不超過餘額不再詢問「是否分期」。
2. 按共用規則查重、保存操作 ID 和原值、選擇受驗證的既有交易入口。直接 Notion 寫入須符合共用的單一寫入與恢復條件；不能跳過網站的未完成交易鎖。
3. 更新原排程 `實收金額=R`、正確「狀態」及最新「收款日期」，保留原「應收金額」、類型、備註和既有關聯。不用本次 A 覆蓋歷次實收。
4. 無排程且來源已給應收 E，可建立說明、應收、實收 A、類型、收款日期、狀態與 `Related to 案件財務管理 (收款紀錄)`；若應收總額未知，先釐清排程範圍，不能以 A 自動表示全案／全期收清。
5. 本次 A 建立一筆分錄，交易類型「收入入帳」，確認的借貸科目與相等金額，填 `關聯收款紀錄` 與 `關聯案件`。已掛應收依原帳沖銷；未掛且確認直接認列才用對應收入科目。每次收款各有分錄保留歷次日期，累計排程本身不代替交易歷史。
6. 讀回排程實收 R、分錄、本案已收及入帳合計、帳戶變動。任何部分寫入／逾時依原 operationId 查核，禁止重新把 A 加一次。

## 回報

列案件／期別／本次實收／累計實收／排程未收／狀態，附排程和分錄連結、帳戶與查核結果。尚未寫入或部分完成須明示，不宣稱已收款登記完成。

不觸碰發包管理已付金額，退款／退票等另確認更正交易，不能用負額普通收款掩蓋。
