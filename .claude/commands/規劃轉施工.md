# 規劃轉施工

把規劃中案件的 Dropbox 資料夾搬移到施工中案件，同時將內部結構（A-I）升級為施工案件結構（A-P），並同步更新 Notion 頁面。

觸發方式：
- `/規劃轉施工 資料夾路徑`
- 例（Mac）：`/規劃轉施工 /Users/tuzhenghong/Library/CloudStorage/Dropbox/宏祐/規劃中案件/202604-國軍左營岡山分院翔青健康管理大樓新建工程`
- 例（Windows）：`/規劃轉施工 D:\Dropbox\宏祐\規劃中案件\202604-國軍左營岡山分院翔青健康管理大樓新建工程`

## 執行步驟

### Step 0：確認路徑與平台

```bash
uname -s 2>/dev/null || echo Windows
```

從使用者輸入取得 `$BASE`（資料夾完整路徑）。

依平台設定：
- **Mac (Darwin)**：`$NODE` = `~/.nvm/versions/node/v24.14.1/bin/node`
- **Windows**：`$NODE` = `C:\Users\deco01\nodejs\node.exe`

使用 **AskUserQuestion** 詢問集團：
- 問題：「這個案件屬於哪個集團？」
- 選項：宏祐集團 / YUSHI

依回答設定 `$集團`。

列出現有資料夾確認：

```bash
$NODE -e "
const fs = require('fs');
console.log(fs.readdirSync('$BASE').sort().join('\n'));
"
```

**執行前提醒使用者：此操作會直接改動資料夾結構，請先確認 Dropbox 已同步完成。**

### Step 0.5：將資料夾從「規劃中案件」搬移至「施工中案件」

從 `$BASE` 路徑判斷 Dropbox 根目錄與集團，組出目標路徑：

- 宏祐集團（Mac）：`$DROPBOX_ROOT` = `/Users/tuzhenghong/Library/CloudStorage/Dropbox/宏祐`
- 宏祐集團（Windows）：`$DROPBOX_ROOT` = `D:\Dropbox\宏祐`
- YUSHI（Mac）：`$DROPBOX_ROOT` = `/Users/tuzhenghong/Library/CloudStorage/Dropbox/yushi`
- YUSHI（Windows）：`$DROPBOX_ROOT` = `D:\Dropbox\yushi`

```
$FOLDER_NAME = 取 $BASE 最後一段（案件資料夾名稱）
$SRC = $BASE（應在 規劃中案件/ 下）
$DST = $DROPBOX_ROOT/施工中案件/$FOLDER_NAME
```

使用 Node.js 執行搬移：

```js
const fs = require('fs');
const path = require('path');
const src = '$SRC';
const dst = '$DST';

if (!fs.existsSync(src)) {
  console.error('❌ 來源路徑不存在：', src); process.exit(1);
}
if (fs.existsSync(dst)) {
  console.error('❌ 目標路徑已存在：', dst); process.exit(1);
}
fs.mkdirSync(path.dirname(dst), { recursive: true });
fs.renameSync(src, dst);
console.log('✅ 搬移完成：', src, '→', dst);
```

搬移成功後，**更新 `$BASE` = `$DST`**，後續所有步驟都用新路徑。

### Step 1：重新命名現有資料夾

使用 Node.js 依序執行（順序重要，避免衝突）：

```bash
$NODE -e "
const fs = require('fs');
const path = require('path');
const BASE = '$BASE';

function mv(src, dest) {
  const srcPath = path.join(BASE, src);
  const destPath = path.join(BASE, dest);
  if (fs.existsSync(srcPath)) {
    fs.renameSync(srcPath, destPath);
    console.log('✅', src, '→', dest);
  }
}

mv('I其他', 'Z其他');           // 先搬走避免衝突
mv('E業主合同資料', 'B業主提供合同資料');
mv('C簡報資料', 'E簡報資料');

mv('B規劃圖面', 'K施工圖面');
mv('H照片', 'M照片');
"
```

### Step 4：更新 Notion 頁面

**4a. 搜尋對應的 Notion 頁面（依資料夾名稱關鍵字）：**

使用 `mcp__notion__API-post-search`，query 為案件名稱關鍵字，找到對應 page_id。

**4b. 更新狀態與集團：**

使用 `mcp__notion__API-patch-page`：
```json
{
  "page_id": "$PAGE_ID",
  "properties": {
    "狀態": { "status": { "name": "工程進行中" } },
    "集團": { "select": { "name": "$集團" } }
  }
}
```

> Notion Projects 資料庫可用狀態（依流程順序）：
> 規劃中 → 工程進行中 → 審核中 → 工程驗收中 → 工程完成請款中 → 專案完成
> 其他：延遲、未承接

**4c. 清除現有頁面內容，重建 A-P 折疊標題：**

```bash
$NODE -e "
const TOKEN = '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';

### Step 4d：建立案件財務管理記錄

**依集團不同，處理方式不同：**

```

若選「否」：跳過，Step 5 摘要標記「⚠️ 案件財務管理尚未建立」。
若選「是」：繼續執行下方建立流程。

#### YUSHI → 直接建立，不詢問

---

**建立流程（宏祐選「是」或 YUSHI 直接執行）：**

追問承攬金額：
```
問題：「承攬金額是多少？（未定可留空）」
選項：
  - 輸入金額
  - 尚未確定，先留空
```

使用 `mcp__notion__API-post-page`（Windows 用 `mcp__notion-win__API-post-page`）在「案件財務管理」資料庫建立記錄，連結至 Projects 頁面：

```json
{
  "parent": { "database_id": "2f97aebd-089f-80f7-9607-df6dc41ab3bd" },
  "properties": {
    "專案名稱": { "title": [{ "text": { "content": "$CASE_NAME" } }] },
    "開始日期": { "date": { "start": "$TODAY" } },
    "專案管理": { "relation": [{ "id": "$PAGE_ID" }] },
    "狀態": { "status": { "name": "進行中" } }
  }
}
```

> 承攬金額已知則加入 `"承攬金額": { "number": $承攬金額 }`；選「尚未確定」則省略，之後在 Notion 補填。

記下回傳的案件財務管理頁面 `$FIN_PAGE_ID`，供下一步使用。

### Step 4e：建立「本案發包明細」表格

> 案件財務管理頁面建立後，立即在頁內建立一個 inline 子資料庫，供日後快速記錄該案件所有發包項目與零星成本（五金零件、加班茶水等），不用等到第一筆發包才臨時建立。

⚠️ `mcp__notion__API-create-a-data-source` 在本環境會回傳 `invalid_request_url`（新版 data source 端點與 MCP server 設定的 `Notion-Version: 2022-06-28` 不相容），改用 curl 直連舊版 `POST https://api.notion.com/v1/databases`：

```bash
curl -s -X POST https://api.notion.com/v1/databases \
  -H "Authorization: Bearer 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" \
  -H "Notion-Version: 2022-06-28" \
  -H "Content-Type: application/json" \
  -d '{
    "parent": {"type": "page_id", "page_id": "'"$FIN_PAGE_ID"'"},
    "title": [{"type": "text", "text": {"content": "本案發包明細"}}],
    "properties": {
      "工種/品項": {"title": {}},
      "廠商": {"rich_text": {}},
      "合約金額": {"number": {"format": "number"}},
      "已付金額": {"number": {"format": "number"}},
      "狀態": {"select": {"options": [
        {"name": "未發包", "color": "gray"},
        {"name": "已發包", "color": "blue"},
        {"name": "施工中", "color": "yellow"},
        {"name": "完工", "color": "green"}
      ]}},
      "備註": {"rich_text": {}}
    }
  }'
```

建立後立即 `PATCH /v1/databases/{回傳的id}` 設定 `{"is_inline": true}`，否則會顯示成連結頁面而非嵌入表格：

```bash
curl -s -X PATCH https://api.notion.com/v1/databases/$NEW_DB_ID \
  -H "Authorization: Bearer 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" \
  -H "Notion-Version: 2022-06-28" \
  -H "Content-Type: application/json" \
  -d '{"is_inline": true}'
```

此時表格為空（尚無發包項目），後續由「報價單輸入資料庫」skill 的 STEP 8 或手動記帳時逐筆填入，**合約金額欄位一律填含稅金額**，與發包管理「成本」欄位一致方便對照。
