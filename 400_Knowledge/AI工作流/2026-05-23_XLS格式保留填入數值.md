## 問題背景

政府標案空白標單（XLS 格式，BIFF8）需要填入廠商報價單價，
但所有 Python/Node 自動化方法都會破壞原始格式（顏色、字型、邊框、欄寬）。

本案：11 張工作表、1210 列、642 工項，填入 20 個廠商報價到 `標單詳細表`。

---

## 嘗試過但失敗的方法

| 方法 | 失敗原因 |
|------|---------|
| xlrd 2.0 + xlutils.copy | xlrd 2.0 移除 `formatting_info=True` 支援 |
| SheetJS (xlsx npm) | 完全不保留格式（顏色/邊框全掉） |
| xlutils.copy + formatting_info=True | xlrd 2.0 不支援，IndexError |
| AppleScript + Excel.app | Mac 上未安裝 Excel，-1728 執行錯誤 |
| AppleScript + Numbers.app | Numbers 無法取得 document 物件 |

## 最終有效方案

### 核心技術

**虛擬環境安裝 xlrd 1.2.0**（最後一個支援 `formatting_info=True` 的版本）：

```bash
python3 -m venv /tmp/xlrd1_env
/tmp/xlrd1_env/bin/pip install "xlrd==1.2.0" xlwt xlutils
```

### 步驟

```python
import xlrd, xlwt, xlwt.Cell as xc
from xlutils.copy import copy as xlcopy

# 1. 讀取原始 XLS，保留所有格式
rb = xlrd.open_workbook(SRC, formatting_info=True)

# 2. 複製為可寫入的 xlwt workbook（保留所有 XF 格式資訊）
wb = xlcopy(rb)
ws_w = wb.get_sheet(rb.sheet_names().index('標單詳細表'))

# 3. 直接操作 xlwt 內部 row dict，取得原始 xf_idx
rows_dict = ws_w._Worksheet__rows
row_obj = rows_dict[row_0]
cells = row_obj._Row__cells

# 取原始 BlankCell 的 xf_idx（保含千分位格式、字型、邊框）
blank_cell = cells[COL_E]
xf_idx = blank_cell.xf_idx

# 4. 替換為 NumberCell（單價），保留 xf_idx
cells[COL_E] = xc.NumberCell(row_0, COL_E, xf_idx, float(unit_price))

# 5. 替換為 FormulaCell（複價），保留 xf_idx
formula = xlwt.Formula(f'D{row_0+1}*E{row_0+1}')
cells[COL_F] = xc.FormulaCell(row_0, COL_F, xf_idx, formula)

wb.save(DST)
```

### 關鍵 bug fix（xlwt Python 3 相容）

```python
import xlwt.BIFFRecords as br
_orig = br.NumberFormatRecord.__init__
def _safe(self, idx, fmtstr):
    if fmtstr is None: fmtstr = ''
    _orig(self, idx, fmtstr)
br.NumberFormatRecord.__init__ = _safe
```

## 重要觀念

### XLS 內部欄位結構（BIFF8）

| xlrd ctype | 對應 BIFF record | 說明 |
|-----------|-----------------|------|
| 0 = empty | 無 record | 完全空白，無格式 |
| 6 = blank | `BLANK (0x0201)` | 有格式但無數值（空白標單的 E 欄） |
| 2 = number | `NUMBER (0x0203)` | 有數值的數字格 |
| 1 = text（讀到） | `FORMULA (0x0006)` | xlwt 寫公式時 cached value 為空字串，xlrd 讀到 ctype=1，但開啟後會重算 |

### xlutils.copy 的 XF 重映射

- 原始 XF 70（xlrd 1.2 讀到）→ 複製後變成 XF 25（xlwt 內部重編號）
- 格式字串完全相同，只是 index 不同
- **必須從 copied workbook 的 BlankCell.xf_idx 取值，不能用原始的 70**

### FormulaCell ctype=1 是正常的

xlwt 寫入 FORMULA record 時，cached value 預設為 `\x00\x00\x00\x00\x00\x00\x01\x00`（空字串標記），所以 xlrd 讀回來是 ctype=1 空值。
但 RPN formula bytes 是完整的 `=D45*E45`，開啟後正常計算。

## 與 PDF 轉 Excel 工作流的關係

這兩個場景是同一個根本問題：

```
【場景 A：PDF 轉 Excel 模板】
PDF 報價單（廠商數字）
  ↓ OCR / 手動解析
數值 → 填入有格式的 XLS 模板
❌ 舊做法（SheetJS / xlrd 2.0）：格式全跑掉，只有數字
✅ 本技術：xf_idx 保留，顏色/字型/邊框/千分位全部不動

【場景 B：標單填報價（本次）】
廠商報價單（祺晟 + 明登）
  ↓ /報價單輸入資料庫 Skill
Notion DB 紀錄 + 本技術
  ↓
政府空白標單 XLS → 填入單價 + =D*E 公式，保留格式
```

**通用規則：只要需要「把數字填進現有 XLS 且不動格式」，就用本技術。**
不論數字來源是 PDF 解析、Notion 資料庫、還是手動輸入，方法相同。
