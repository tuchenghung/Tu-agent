# 佑祥公司記帳系統

> 建立時間：2026-06-05
> 類型：新功能
> 狀態：執行中（Step 1-4 完成，Step 4 待部署 Streamlit Cloud）

## 你要做的事（一句話版）
在 Notion 建立 4 張互連資料庫做手機記帳，搭配 Streamlit 雲端財報儀表板，讓你隨時查看每個工程案件的收支、廠商付款進度、公司整體損益。

## 背景和動機
- 現有工具 CM Money 是個人記帳軟體，沒有「案件」維度，無法追蹤工程公司的發包/收款結構
- 佑祥同時有多個案件（業主分期收款）+ 多家廠商（分批付款），需要一個能對帳的工具
- 目標：每月或每半年能產出損益表、現金流表，做公司復盤

## 資料庫架構（Notion 4 張表）

```
案件總覽 (Projects)
  ├── 收款記錄 (Revenue)     ← 業主付款進度
  └── 廠商發包 (Contracts)
        └── 廠商付款紀錄 (Payments)  ← 廠商分批付款
```

### DB1：案件總覽
| 欄位 | 類型 | 說明 |
|------|------|------|
| 案件名稱 | Title | |
| 合約總金額 | Number | 業主合約價 |
| 發包總金額 | Rollup | 從廠商發包加總 |
| 已收款金額 | Rollup | 從收款記錄加總 |
| 已付廠商金額 | Rollup | 從廠商付款加總 |
| 毛利（試算）| Formula | 已收 − 已付 |
| 狀態 | Select | 規劃中/進行中/完工/結案 |
| 開始日期 | Date | |

### DB2：收款記錄（業主）
| 欄位 | 類型 | 說明 |
|------|------|------|
| 說明 | Title | 例：開工款、完工款、追加工程款 |
| 案件 | Relation → DB1 | |
| 應收金額 | Number | |
| 實收金額 | Number | |
| 收款日期 | Date | |
| 狀態 | Select | 待收/已收/部分收 |
| 應收未收 | Formula | 應收 − 實收 |

### DB3：廠商發包
| 欄位 | 類型 | 說明 |
|------|------|------|
| 發包說明 | Title | 例：水電工程、輕隔間 |
| 案件 | Relation → DB1 | |
| 廠商名稱 | Relation → 供應商DB | |
| 發包金額（議價後） | Number | |
| 工程項目 | Multi-select | |
| 已付金額 | Rollup | 從 DB4 加總 |
| 應付未付 | Formula | 發包金額 − 已付 |

### DB4：廠商付款紀錄
| 欄位 | 類型 | 說明 |
|------|------|------|
| 說明 | Title | 例：第一期款 |
| 發包單 | Relation → DB3 | |
| 付款金額 | Number | |
| 付款日期 | Date | |
| 付款方式 | Select | 轉帳/現金/支票 |
| 備註 | Text | |

## 具體步驟

### Step 1：在 Notion 建立 4 張資料庫
- 做什麼：在「佑祥工程管理」頁面下建立 DB1~DB4，設定關聯與公式
- 產出：可在手機輸入、查詢的記帳資料庫
- 注意：DB3 廠商欄位連結到現有「供應商資料庫」（若有）

### Step 2：匯入現有資料
- 做什麼：把目前手上有的案件、廠商資料、已有付款記錄輸入進去
- 產出：資料庫有初始資料，測試關聯是否正確
- 注意：截圖中的追加工程款流水帳也要一起匯入

### Step 3：建立 Streamlit 財報 App
- 做什麼：寫一個 Streamlit App，透過 Notion API 讀取 4 張資料庫
- 產出：本地可跑的財報儀表板，包含：
  - 案件收支總覽（各案毛利一覽表）
  - 廠商應付未付列表
  - 全公司月度收支彙總
  - 現金流量（收款日期 vs 付款日期）
- 技術：Python `notion-client` 套件 + `pandas` + `streamlit`
- 注意：放在 `000_Agent/tools/yushiang-accounting/` 與 cleanroom-hvac 並列

### Step 4：Streamlit Cloud 部署（手機可存取）
- 做什麼：將 App 推到 GitHub（私人 repo），連結 Streamlit Cloud 免費部署
- 產出：一個固定 URL，手機瀏覽器就能查看財報
- 注意：Notion API Token 設定為 Streamlit Cloud Secret，不寫進程式碼

### Step 5：建立現金/銀行餘額追蹤
- 做什麼：在 Notion 或 Streamlit 加一個「公司銀行帳戶餘額」手動登記欄位
- 產出：Streamlit 首頁顯示目前銀行存款 + 應收未收 + 應付未付
- 注意：這是手動更新，未來可接銀行 API（超出本次範圍）

## 預計成果
- Notion 手機 App 可直接輸入每筆收款/付款
- Streamlit 財報頁（手機/PC 均可開）：毛利、廠商應付、月度現金流
- 每半年可從 Streamlit 匯出報表做復盤

## 不包含在這次的範圍
- 自動讀取銀行對帳單（需銀行 API）
- 發票 / 統編管理（另外討論）
- 稅務計算（需會計師確認科目）
- 完整 GAAP 資產負債表（第一階段先做管理用財報）

## 可能遇到的風險
- **Notion API 速率限制**：Streamlit 每次整頁重整都打 API，大量資料可能慢 → 加 cache 機制
- **Streamlit Cloud 免費版休眠**：閒置 30 分鐘會休眠，第一次打開需等 30 秒 → 可接受
- **GitHub 私人 repo 同步**：需要設定 git，和現有 Dropbox 工作流分開管理
